# बोल्ट सेंड पार्सल एपीआई (Bolt Send API) — शराब पार्सल डिलीवरी हेतु एडवांस्ड आरएंडडी एवं आर्किटेक्चर रिपोर्ट

---

## 1. सारांश एवं आरएंडडी निष्कर्ष (Executive Summary & R&D Verdict)

### 1.1 उद्देश्य (Objective)
**बोल्ट राइड बुकर / बोल्ट सेंड एपीआई (Bolt Send API)** (`https://ridebooker.bolt.eu/api-docs`) का विस्तृत तकनीकी विश्लेषण (R&D) करना और यह तय करना कि क्या इसे **LiquorJunction** (`admin.new.liquorjunctionghana.com`) प्लेटफॉर्म में केवल एक चयनित देश (**घाना: अक्रा, कुमासी**) के भीतर ऑन-डिमांड **शराब पार्सल डिलीवरी (Unaccompanied Parcel Delivery)** के लिए **ऑर्डर करने से लेकर डिलीवरी और बिलिंग समाधान तक (End-to-End Advanced Lifecycle)** उपयोग किया जा सकता है।

### 1.2 अंतिम फिजिबिलिटी निष्कर्ष: **"BOLT SEND" (`vehicle_category: "delivery"`) द्वारा पूरी तरह संभव है**
| मूल्यांकन मापदंड (Metric) | स्थिति (Status) | विवरण (Details) |
| :--- | :---: | :--- |
| **आधिकारिक पार्सल मोड (Bolt Send)** | ✅ **समर्थित (Supported)** | बोल्ट घाना (Accra, Kumasi आदि) में आधिकारिक रूप से **"Bolt Send"** पार्सल सेवा संचालित करता है। एपीआई स्कीमा में इसे `vehicle_category: "delivery"` या `"motorbike"` द्वारा दर्शाया गया है। |
| **बिना यात्री की डिलीवरी (No Passenger)** | ✅ **गारंटीकृत (Guaranteed)** | बोल्ट सेंड में **गाड़ी में कोई यात्री नहीं बैठता**। वाहन केवल दुकान से ग्राहक तक सीलबंद डिब्बा पहुंचाने के लिए भेजा जाता है। |
| **सुरक्षित सिंगल पार्सल (Single-Package Security)** | ✅ **गारंटीकृत (Guaranteed)** | "एक ट्रिप = एक पार्सल": बोल्ट ड्राइवर एक बार में केवल एक ही ऑर्डर लेकर जाता है, जिससे पार्सल अदल-बदल होने का कोई खतरा नहीं रहता। |
| **कस्टमर पिनअप व एडमिन ऑनलाइन डिस्पैच** | ✅ **अनुकूलित कार्यप्रवाह** | ग्राहक चेकआउट पर केवल मैप पर लोकेशन पिन करता है (**चेकआउट पर बोल्ट एपीआई की कोई कॉल नहीं होती**)। एडमिन पैनल में केवल **ऑनलाइन पेड ऑर्डर्स** पर ही बोल्ट सेंड द्वारा पार्सल डिस्पैच का विकल्प अनलॉक होता है। |
| **केवल एक देश में संचालन (Single-Country Restriction)** | ✅ **समर्थित (Supported)** | बुकिंग अक्षांश और देशांतर (`latitude`, `longitude`) पर आधारित होती है। स्टोर और ग्राहक के पते को घाना के कोऑर्डिनेट्स में जियोफेंस (Geofence) करके केवल उसी देश में सीमित रखा जा सकता है। |
| **जियोकोडिंग और लोकेशन चयन (Geocoding / Pin Picker)** | 🔴 **अनिवार्य आवश्यकता (Mandatory)** | बोल्ट एपीआई टेक्स्ट एड्रेस स्वीकार नहीं करता। इसे अनिवार्य रूप से दशमलव कोऑर्डिनेट्स (`lat`, `lng`) चाहिए। चेकआउट/एड्रेस पेज पर गूगल मैप्स पिन और लोकेशन चयन होना **100% अनिवार्य** है। |
| **वेबहुक डेटाबेस ऑडिट लॉगिंग (Webhook Database Logging)** | 🔴 **प्रोडक्शन हेतु जरूरी (Critical)** | प्रत्येक वेबहुक कॉल का पूरा कच्चा डेटा (`headers`, `payload`, `ip`, `status`, `response`) `bolt_webhook_logs` तालिका में सुरक्षित होना चाहिए ताकि "कब, क्या, कैसे कॉल हुआ" का पूरा ऑडिट रहे। |
| **हैंडओवर का तरीका (Curbside Delivery)** | ⚠️ **कर्बसाइड मॉडल** | बोल्ट सेंड **कर्बसाइड (Curbside)** आधार पर काम करता है: स्टोर का स्टाफ बाहर सड़क पर गाड़ी के पास आकर ड्राइवर को बॉक्स देगा; और ग्राहक अपने घर के गेट/सड़क पर आकर ड्राइवर से बॉक्स लेगा। |
| **बिलिंग मॉडल (Billing Model)** | ✅ **सेंट्रलाइज्ड (Centralized)** | सारा भुगतान सीधे कंपनी के बोल्ट बिजनेस अकाउंट (`payment_method: "business"`) से कटता है, ड्राइवर और स्टोर के बीच कैश का कोई झंझट नहीं होता। |

## 2. संपूर्ण एडवांस्ड लाइफसाइकिल: ऑर्डर से डिलीवरी तक (End-to-End Stages)

एक मजबूत ई-कॉमर्स सिस्टम में केवल एपीआई कॉल करना काफी नहीं होता; उसमें पैकिंग गेट, किराए की वैधता, सड़क पर हैंडओवर और अपवादों (Exceptions) को संभालना जरूरी होता है:

```
+-------------------------------------------------------------------------------------------------------------------------+
|                                    बोल्ट सेंड डिलीवरी की संपूर्ण एडवांस्ड लाइफसाइकिल                                   |
|                                                                                                                         |
| [ स्टेज 1: चेकआउट पर लोकेशन पिनअप व पेमेंट (नो बोल्ट एपीआई कॉल) ]                                                        |
| ग्राहक चेकआउट पर गूगल मैप पर अपने घर का गेट पिन करता है -> lat/lng को user_address और order में सेव किया जाता है ->      |
| सामान्य डिलीवरी चार्ज जुड़ता है -> ग्राहक ऑनलाइन पेमेंट (MojoPay) पूरा करता है। चेकआउट पर कोई बोल्ट कॉल नहीं होती।       |
|                                                                                                                         |

| ऑर्डर कन्फर्म हुआ -> वेयरहाउस को पिक-लिस्ट मिली -> स्टाफ शराब की बोतलों को सीलबंद कार्टन में पैक करता है (मैक्स 15 kg) ->|

|                                                                                                                         |

| स्टाफ बाहर सड़क पर गाड़ी के पास जाकर डिब्बा #LJ-1042 ड्राइवर को सौंपता है।                                              |
|                                                                                                                         |
```

## 3. एडवांस्ड एज-केस और एरर रिकवरी (Edge Cases & Exception Handling)

जमीनी हकीकत में आने वाली समस्याओं का ऑटोमैटिक समाधान:

### 3.1 किराए की आईडी एक्सपायर होना (`fare_id` Expired)
* **समस्या**: बोल्ट का `fare_id` 2 से 5 मिनट में एक्सपायर हो जाता है ताकि सर्च प्राइसिंग बदल सके।
* **समाधान**: जब एडमिन डिस्पैच बटन दबाता है, तो सिस्टम चेक करता है कि कोटेशन 2 मिनट से ज्यादा पुराना तो नहीं है। यदि पुराना है, तो सिस्टम बैकग्राउंड में तुरंत नया `fare_id` लेकर ही `/rides/create` कॉल करता है।

### 3.2 नजदीकी ड्राइवर उपलब्ध न होना (`NO_DRIVERS_AVAILABLE`)
* **समस्या**: बारिश या ट्रैफिक के समय अक्रा में तुरंत कोई बोल्ट बाइक/कार उपलब्ध न हो।
* **समाधान**:
  1. सिस्टम 90 सेकंड के अंतराल पर 3 बार ऑटोमैटिक री-ट्राई करता है।
  2. यदि 5 मिनट तक ड्राइवर न मिले, तो एडमिन स्क्रीन पर विकल्प आता है: *"बोल्ट कूरियर व्यस्त हैं। [पुनः प्रयास करें] या [दुकान का अपना राइडर असाइन करें]"*।

### 3.3 रास्ते में ड्राइवर द्वारा राइड कैंसिल होना
* **समस्या**: ड्राइवर ने राइड एक्सेप्ट की, लेकिन रास्ते में गाड़ी खराब होने पर उसने कैंसिल कर दिया।
* **समाधान**: बोल्ट का वेबहुक तुरंत स्टेटस को वापस `SEARCHING` या `CANCELLED` भेजेगा। हमारा वेबहुक कंट्रोलर इसे पहचानकर एडमिन को अलर्ट देगा और नया ड्राइवर ढूंढने का ऑटो-डिस्पैच शुरू कर देगा।

### 3.4 ग्राहक द्वारा फोन न उठाना (Unreachable Customer)
* **समस्या**: ड्राइवर ग्राहक के पते पर पहुंचा लेकिन ग्राहक फोन नहीं उठा रहा।
* **समाधान**: बोल्ट ड्राइवर गंतव्य पर 5 मिनट इंतजार करता है। यदि संपर्क न हो, तो पार्सल वापस स्टोर लाया जाता है। वेबहुक इसका रिकॉर्ड रखता है और ऑर्डर का स्टेटस `delivery_unreachable` हो जाता है।

### 3.5 मैन्युअल कैंसलेशन फीस की जांच
* **समस्या**: ड्राइवर बुलाने के बाद ग्राहक ने ऑर्डर कैंसिल कर दिया।
* **समाधान**: `/rides/cancel` कॉल करने से पहले सिस्टम `GET /rides/cancellation_fee` कॉल करता है। यदि कोई कैंसलेशन फीस लग रही हो, तो एडमिन को स्क्रीन पर फीस दिखाकर कन्फर्मेशन मांगा जाता है।

## 4. बोल्ट सेंड पार्सल विनिर्देश और सीमाएं (Package Limits)

* **अधिकतम वजन**: **15 किलोग्राम** (6 से 12 वाइन या व्हिस्की की बोतलों के लिए पर्याप्त)।
* **अधिकतम आकार**: **65 × 55 × 40 सेमी** (डिक्की या बाइक बैग में आसानी से फिट)।
* **हैंडओवर नियम**: **कर्बसाइड हैंडओवर (Curbside)**। पिकअप और डिलीवरी दोनों बाहर सड़क पर गाड़ी के पास होते हैं।
* **पैकिंग मानक**: कांच की बोतलें बबल-रैप और सीलबंद डिब्बे में होनी चाहिए।

## 5. जियोकोडिंग और लोकेशन चयन रणनीति (Geocoding & Location Picker)

### 5.1 तकनीकी अनिवार्यता
बोल्ट के एंडपॉइंट्स (`POST /reseller/v2/rides/estimations` और `POST /reseller/v1/rides/create`) में केवल अक्षांश व देशांतर (`lat`, `lng`) स्वीकार किए जाते हैं:
```json
"stops": [
  { "lat": 5.6037, "lng": -0.1870 },
  { "lat": 5.6320, "lng": -0.1654 }
]
```

### 5.2 3-स्तरीय समाधान:
1. **गूगल प्लेसेस ऑटो-कम्प्लीट**: घाना के पतों को सर्च करने की सुविधा।
2. **इंटरएक्टिव मैप पिन पिकर**: ग्राहक मैप पर लाल पिन को अपने गेट पर ड्रैग कर सकता है या "Use Current Location" (GPS) चुन सकता है।
3. **बैकएंड ऑटोमैटिक फॉलबैक**: यदि किसी पुराने पते में lat/lng नहीं है, तो `GeocodingService` टेक्स्ट पते को गूगल जियोकोडिंग एपीआई से lat/lng में बदल देती है।

## 7. वेबहुक और डेटाबेस ऑडिट लॉगिंग (bolt_webhook_logs)

```sql

  `id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `event_id` VARCHAR(191) NULL INDEX,
  `event_type` VARCHAR(100) NULL INDEX,
  `ride_id` VARCHAR(100) NULL INDEX,
  `state` VARCHAR(50) NULL INDEX,
  `headers` JSON NULL,
  `payload` JSON NOT NULL,
  `ip_address` VARCHAR(45) NULL,
  `status` ENUM('RECEIVED', 'PROCESSED', 'FAILED', 'UNAUTHORIZED', 'IGNORED') DEFAULT 'RECEIVED',
  `response_code` INT DEFAULT 200,
  `response_body` JSON NULL,
  `error_message` TEXT NULL,
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 7.1 बोल्ट सेंड स्टेटस मैपिंग
| बोल्ट स्टेट | बोल्ट सेंड में अर्थ | ऑर्डर का स्टेटस | सिस्टम एक्शन |
| :--- | :--- | :--- | :--- |
| `SEARCHING` | अक्रा में बोल्ट सेंड कूरियर खोजा जा रहा है | `Processing / Dispatching` | सर्चिंग दिखाएं; लॉग सेव करें |
| `DRIVER_ON_ROUTE_TO_CLIENT` | ड्राइवर पार्सल लेने दुकान की ओर आ रहा है | `Driver Assigned` | स्टोर स्टाफ को कार्टन बाहर लाने का अलर्ट दें; ड्राइवर की डिटेल सेव करें |
| `ARRIVED_AT_CLIENT` | ड्राइवर दुकान के बाहर सड़क पर पहुंच गया | `At Store / Pickup` | स्टोर स्टाफ ड्राइवर को सीलबंद बॉक्स सौंपे |
| `DRIVING_WITH_CLIENT` | ड्राइवर डिब्बा लेकर ग्राहक के घर की तरफ रवाना | `Out for Delivery` | ग्राहक को लाइव जीपीएस ट्रैकिंग लिंक (`tracking_url`) का SMS भेजें |
| `COMPLETED` | ग्राहक ने अपने गेट पर पार्सल प्राप्त किया | `Delivered` | डिलीवरी ईमेल भेजें और इनवॉइस रसीद सेव करें |
| `CANCELLED` | डिलीवरी रद्द हुई | `Delivery Failed` | स्टोर मैनेजर को अलर्ट दें ताकि दोबारा कूरियर बुक किया जा सके |
